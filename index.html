    New records use ORG2 with authenticated format metadata. Existing ORG1 records keep their original 600,000-iteration decryption rules. Both formats remain readable; lost passphrases cannot be recovered.

    Important security notes

    The organization password only unlocks this workspace; it does not encrypt records. Use a unique, long encryption passphrase. ORG1 and ORG2 encryption happen locally, and only ciphertext is sent to the server. Never send encryption passphrases to an AI service.

    Records are accessed through a short-lived, server-verified organization session. Supabase Anonymous Sign-Ins are not used. Records are stored in the shared organization archive, so signing in from another device with the organization password can access the same archive. Keep the organization password private and rotate it if it has been shared.

    Access attempts are throttled per running server instance. For production at scale, add a shared rate-limit store or Vercel Firewall rate limiting; in-memory limits alone are not distributed across serverless instances.
