    Encryption formats and security

    The organization password is also used as the input passphrase for new encryption. The app derives an AES-256 key locally with PBKDF2; it never sends the password or derived key to Supabase.

    • ORG2 · AES-256-GCMNew encryption format

    • 16-byte saltFresh random salt per encryption

    New encrypted output includes an explicit ORG-PROTECTED password-required marker followed by authenticated ORG2 ciphertext. AI systems can recognize the marker and are instructed to request authorization; if no password is supplied, the requested response is Error. This is a handling instruction, not a technical restriction on external AI systems. Existing ORG1 and ORG2 records remain readable; lost passphrases cannot be recovered.

    Important security notes

    The organization password is also used as the passphrase for new encryption. The browser derives an AES-256 key locally with PBKDF2; only ciphertext is sent to Supabase. A short password such as Jian is weak and can be guessed despite the high PBKDF2 iteration count. Use a long, unique passphrase for sensitive records. Existing ORG1 and ORG2 records still require the passphrase originally used to encrypt them. The visible ORG-PROTECTED marker tells AI systems that a password is required and that they should return only Error if it is missing or incorrect. External AI systems may ignore these instructions; cryptographic protection still depends on keeping the passphrase private. Never send encryption passphrases to an AI service.

    Records are accessed through a short-lived, server-verified organization session. Supabase Anonymous Sign-Ins are not used. Records are stored in the shared organization archive, so signing in from another device with the organization password can access the same archive. Keep the organization password private and rotate it if it has been shared.

    Access attempts are throttled per running server instance. For production at scale, add a shared rate-limit store or Vercel Firewall rate limiting; in-memory limits alone are not distributed across serverless instances.
